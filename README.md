# autoprep

Competitive programming and quant-interview prep in one site.

- **Codeforces path.** Three tracks in learning order:
  - **Dynamic programming:** prefix and suffix sums, difference arrays, DP states, LIS/LDS, LCS and edit distance, knapsack, grid and interval DP, bitmask DP, and DP sped up with Fenwick and segment trees.
  - **Graphs:** DFS, BFS, trees, DSU and MST, topological sort, shortest paths, binary lifting.
  - **Geometry:** binary and ternary search on the answer, geometry basics, convex hulls.

  Each stage has a primer covering the idea, when to reach for it, how it hides in a statement, common bugs, a C++ template and links. It then lists Codeforces problems sorted by rating with no jump bigger than 300. Every problem has three progressive hints and a solution sketch. Hint 1 nudges, hint 2 names what the problem really is (for example "longest non-decreasing subsequence in disguise"), and hint 3 gives the approach. Each hint was written after solving the problem and checking the solution on the statement's samples.
- **UKIEPC practice.** Every problem from UKIEPC 2023, 2024 and 2025 (Codeforces gyms 104785, 105446 and 106157), with hints based on the official jury solutions. Each problem's difficulty and the path stages it relies on are hidden by default to avoid spoilers; switch them on with the toggles. Each year is collapsed until you open it. A problem is marked as covered once you've completed its stages.
- **Mental maths.** A Zetamac-style round with Zetamac's settings: addition ranges (subtraction is the reverse), multiplication ranges (division is the reverse), and 30–600 seconds. It can also add decimals (off, mixed or only, with 1 or 2 decimal places), like the trading-firm tests that use them. Every answer is timed and tagged with the skill it uses. Afterwards you get the technique costing you the most, a worked explanation, and a drill on just that kind of question.

Codeforces sync is optional: enter a handle and accepted problems (including gym submissions) are ticked off. Settings, rounds, solved problems, revealed hints and page preferences are stored in your browser's `localStorage`, but only after you accept the storage notice. Until then, or if you choose "Not now", nothing is written. There's no backend and no build step.

Each stage's primer has a step-through diagram of its algorithm on a small example, one elementary step per frame: every LCS and knapsack cell with the cells it reads, every BFS dequeue, every Dijkstra relaxation, every push and pop of the convex hull, and so on. Play, step, drag the slider to any step or change the playback speed. Each step's caption is read aloud as it's shown, and Play waits for the voice before moving on; the speaker button mutes this for every diagram. The frames are generated by running the real algorithm (`src/viz/stages/`). Mental-maths lessons draw the method for whichever example is on screen: columns and carries, number lines, area models, aligned decimal points (`src/viz/maths.js`).

Primers, hints, solutions and lessons can be read aloud, with notation spoken as words and the paragraph being read highlighted (`src/tts.js`). While a page is being read, click any paragraph to jump ahead or back to it. The default voice is Heart from [Kokoro](https://huggingface.co/hexgrad/Kokoro-82M), pre-recorded for every paragraph and diagram step on the site (`audio/`), so it starts at once on any device. Speed goes from 0.25× to 1.75× without changing pitch. Text that isn't recorded, such as a fresh worked example, uses the browser's voice. The other natural voices run the Kokoro model on your graphics card through WebGPU, after you agree to its one-time 330 MB download. Browser voices can be picked too. The recorded and model voices send nothing anywhere; some browsers' online voices are made on their maker's servers.

Each stage's code template can be switched between general code and a version written against [the TRD](https://github.com/alan-d-smith/competitive-programming/tree/main/trd) (KACTL-based), using its macros and components. KACTL components the TRD doesn't include are marked (`src/cf/trd.js`). Every TRD version compiles with `g++ -std=c++20` against the real headers.

Each stage also links one or two short explainer videos from well-known channels (WilliamFiset, Errichto, Tushar Roy, Reducible, 3Blue1Brown and others), all under 30 minutes (`src/cf/videos.js`). Nothing loads from YouTube until you press play; then the video plays from youtube-nocookie.com.

The path's stage list floats on the left and can be hidden for a wider page. Each track folds away, and each stage opens to list its problems; clicking one jumps to it. Hints and primers show notation like `dp[i][j]`, `O(n log n)` and `10^9` as inline code and superscripts (`src/format.js`). Templates get C++ syntax highlighting.

## Run it

```sh
npm run dev      # http://localhost:5173
npm test         # engine, diagnosis, curriculum and UKIEPC data tests
npm run verify:curriculum   # re-check every problem's name and rating against the Codeforces API
```

Node 20+ is only needed for the dev server and tests. The site itself is static files: `index.html`, `styles.css`, `favicon.svg`, `fonts/`, `audio/` and `src/`. Because it uses ES modules, open it through a server rather than straight from the file system. Deploy to Vercel (or any static host) from the repo root, with framework preset **Other**, no build command, and output directory `.`.

## How the mental-maths diagnosis works

`src/math/diagnose.js` models each question's time as *your pace × how hard that kind of question is*. The difficulty weights live in `src/math/skills.js`. Your goal score (automatic by default) turns into a target time for every skill. Two things can make a skill the focus:

1. **A gap.** It's much slower than your own pace predicts (at least 1.3×), and closing the gap is worth about a point a round or more. That points to a missing technique, which is the quickest thing to fix, so gaps come first.
2. **A cost.** With no gap, the focus is the skill costing the most correct answers per round against your goal.

Small samples are handled conservatively. Each estimate is pulled toward your overall pace until there's enough evidence. The previous two rounds count at half and quarter weight. A single freeze is capped at 5× your median time. Classification works for any ranges: carries and borrows are checked column by column, trailing zeros are ignored (7 × 60 counts as a times-table fact), and widening the ranges adds two-digit × two-digit and two-digit-divisor skills.

## Editing content

- Tracks and stage order: `src/cf/curriculum.js`.
- A stage's primer, problems and hints: `src/cf/stages/<stage>.js`. Problem IDs are `contestId + index` (e.g. `1201C`). Run `npm test` and `npm run verify:curriculum` after changes.
- UKIEPC problems: `src/cf/ukiepc.js`.
- Mental-maths skills, lessons and worked steps: `src/math/skills.js`. The tests check that every skill's worked steps end at the right answer, for both default and wide ranges.
- After changing any text that's read aloud, re-record it (see below). Until then, changed paragraphs are read by the browser's voice.

## Recording the voice

The recordings are made offline from the site's own text:

```sh
npm install                      # playwright-core, to read the pages in your installed Chrome or Edge
npm run audio:texts              # every read-aloud paragraph and diagram caption → audio/texts.json
python scripts/build_audio.py    # records what's missing → audio/af_heart/*.webm and index.json
```

`build_audio.py` needs Python 3.10–3.12 with `pip install kokoro soundfile torch`, and ffmpeg (with libopus) on `PATH` or in `FFMPEG`. On an NVIDIA GPU, install a CUDA build of torch: it's many times faster than the CPU. Clips are named by a hash of their text (`src/audio-key.js`), so reruns only record what changed. `--prune` deletes clips the site no longer uses.

The spoken text is written to sound natural: `P[7] = P[6] + a[6] = 23 + 2 = 25` is read "P of 7 is P of 6 plus A of 6, which is 23 plus 2, so 25", and a variable called `a` is capitalised so it isn't heard as the article. Kokoro still reads some capital As as "uh", so `texts.json` also holds a `script` for those paragraphs in which that A is written "eh", which Kokoro always says as the letter. Recordings are keyed by the script, so pronunciation fixes get re-recorded too.
